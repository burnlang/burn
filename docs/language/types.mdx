# Types and definitions

## Built-in types

| Type | Example |
| --- | --- |
| `int` | `42`, `0x1F`, `1_000_000` |
| `float` | `3.14`, `2.5e-3` |
| `bool` | `true`, `false` |
| `string` | `"text"` |
| `[T]` | `[1, 2, 3]` |
| `{K: V}` | `{"ada": 36}` |
| `T?` | `null` or a `T` |
| `any` | any value, see [smart casts](./smart-casts.mdx) |
| `fun(A, B): R` | a function value |
| `Future<T>` | the result of an `async fun` |

## Everything else is defined with `def`

Every user defined type uses the same shape: `def <kind> Name { ... }`.

### `def type`

A record of named fields. Fields can be written as `name: Type` or `Type name` and may have defaults.

```burn
def type Person {
    name: string,
    age: int,
    active: bool
}

def type Config {
    string host = "localhost"
    int port = 8080
    [string] tags
}

var c = Config { port: 9000 }
var p = Person { name: "Ada", age: 36, active: true }
var q = Person("Grace", 45, true)
```

Records compare by value with `==` and print nicely with `print`.

A `def type` can also name another type:

```burn
def type UserId = int
def type Matrix = [[float]]
```

### Anonymous records

An object literal without a type name gets its type from the context. If nothing is expected, Burn looks for a
single `def type` with exactly those fields, and otherwise creates an anonymous record type:

```burn
fun origin(): Person {
    return { name: "nobody", age: 0, active: false }
}

var point = { x: 1.5, y: 2 }
print(point.x + point.y)
```

### `def enum`

```burn
def enum Color { Red, Green, Blue }

var c = Color.Green
print(c, c == Color.Green, c as int)
```

### `def struct` and `def interface`

Structs hold fields and methods and are created with `new`:

```burn
def struct Point(x: int, y: int) {
    fun sum(): int {
        return x + y
    }
}

var p = new Point(1, 2)
```

See [structs and interfaces](./structs-and-interfaces.mdx) for constructors, inheritance, abstract and static
structs, and destroying objects.

## Arrays

```burn
var numbers = [5, 3, 8]
numbers.push(1)
sort(numbers)
print(numbers[0], numbers.length, contains(numbers, 8))
[[int]] grid = [[1, 2], [3, 4]]
grid[1][0] = 30
```

## Maps

```burn
var ages = {"ada": 36, "alan": 41}
ages["grace"] = 45
print(ages["ada"], has(ages, "bob"), keys(ages))
{string: [int]} scores = {}
```

Reading `map[key]` gives a nullable value, `int?` for the map above, because the key may be missing. Give it a
fallback with `ages["bob"] ?? 0`, check it with `!= null`, or assert with `ages["ada"]!!`.
`get(map, key, default)` still works as well.

## Generics

Functions and types can take type parameters in `<...>`. Burn works out the types from the arguments, so calls look
like normal calls:

```burn
fun first<T>(items: [T]): T? {
    if len(items) == 0 {
        return null
    }
    return items[0]
}

fun mapList<T, U>(items: [T], f: fun(T): U): [U] {
    [U] out = []
    for x in items {
        out.push(f(x))
    }
    return out
}

print(first([3, 4]), first(["a"]))
print(mapList([1, 2, 3], fun(x: int): string {
    return "#${x}"
}))
```

`def type` and `def struct` take type parameters after the name:

```burn
def type Pair<A, B> {
    first: A
    second: B
}

def struct Stack<T>() {
    [T] items = []

    fun push(item: T) {
        items.push(item)
    }

    fun pop(): T? {
        if len(items) == 0 {
            return null
        }
        return items.pop()
    }
}

var p = Pair { first: 1, second: "one" }
Pair<string, bool> q = Pair { first: "yes", second: true }
var s = new Stack<int>()
s.push(1)
```

Write the type arguments when Burn cannot work them out, for example `new Stack<int>()` for an empty stack.

The compiler makes a separate version of the function or type for each set of types it is used with, so generic
code runs as fast as code written for one type, and there is no boxing. A type parameter can be used in any way the
types it is used with allow: `largest<T>` can compare with `>` and works for `int`, `float` and `string`. Using it
with a type that has no `>` is a compile error that points at the comparison and names the version, for example
`largest<bool>`.

Generic structs can implement interfaces. They cannot extend other structs or have static members yet, and
methods cannot have their own type parameters yet.
