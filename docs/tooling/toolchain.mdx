# The toolchain

`burn` is bvm, the Burn virtual machine. Started as `burn`, `burni`, `burnc` or `burn-lsp` (links to it), it runs
the command line written in Burn (`share/burn/burn.bvm`), which checks the name it was started with. `burnfmt` runs
the formatter written in Burn, and `bvm` is the virtual machine on its own.

## `burni`: the interpreter

`burni` type-checks a program, compiles it to a [bvm](../bvm/overview.mdx) module in memory and runs it. There is
no build step: a program starts in a few milliseconds. `burni` also runs `.bvm` and `.bvmc` files.

```sh
burni app.bn                 # run a program
burni app.bn one two         # arguments are available through args()
burni                        # start the REPL
burni -e 'print(6 * 7)'      # run a snippet
burni --version
```

| Usage | Same as |
| --- | --- |
| `burni <file.bn> [args...]` | `burn run <file.bn> [args...]` |
| `burni` | `burn repl` |
| `burni -e '<code>'` | `burn eval '<code>'` |

The REPL keeps variables, functions and types between inputs, prints the value of expression statements and
understands `:help`, `:reset`, `:source` and `:quit`.

## `burnc`: the compiler

`burnc` compiles a program to a standalone native executable, to [bvm](../bvm/overview.mdx) bytecode, which runs
anywhere bvm runs, or to JavaScript for Node.js.

```sh
burnc app.bn                          # ./app
burnc app.bn -o bin/app               # choose the output path
burnc app.bn --emit-asm app.s         # also write the generated assembly
burnc app.bn --target bvm             # app.bvmc, bytecode for bvm
burnc app.bn --target bar             # app.bar, the program and its bytecode libraries in one archive
burnc app.bn --target js              # app.js, a program for Node.js
burnc app.bar -o app                  # a native executable that runs a bytecode archive
burnc app.bn --no-strip               # keep symbols for debuggers and profilers
burnc app.bn --no-std                 # without the standard library
burnc --check a.bn b.bn               # type-check only
```

| Option | Description |
| --- | --- |
| `-o`, `--output <path>` | output file; defaults to the source name without `.bn` (`.bvmc`, `.bar` or `.js` for the other targets) |
| `--target native` | x86-64 machine code linked into an executable (default) |
| `--target bvm` | a `.bvmc` bytecode module, with imported bytecode libraries linked in |
| `--target bar` | a runnable [archive](../bvm/archives.mdx) with the program and its bytecode libraries |
| `--target js` | a JavaScript file for Node.js; it cannot use bytecode libraries, `@Native` functions or mixins |
| `--emit-asm <path>` | write the generated assembly as well (bvm assembly for `--target bvm`) |
| `--no-strip` | keep the symbol table |
| `--no-std` | build [without the standard library](./no-std.mdx) |
| `--check <files...>` | report errors and warnings without producing output |

Native executables need x86-64 Linux or macOS and a C toolchain (`cc`, or the program named by `BURN_CC`), which is
used to assemble and link them with the runtime in `share/burn/lib`. Run bytecode with `burn app.bvmc` or
`bvm app.bvmc`; an archive also runs on its own (`./app.bar`) when `bvm` is on `PATH`, and a JavaScript build with
`node app.js`. See [how the compiler works](./compiler.mdx).

## `burnfmt`: the formatter

`burnfmt` formats Burn source code. It is written in Burn (`lib/tools/fmt.bn`) and runs on bvm. See [burnfmt](./burnfmt.mdx).

```sh
burnfmt file.bn              # print the formatted file
burnfmt -w src/*.bn          # rewrite files in place
burnfmt --check src/*.bn     # list unformatted files, exit code 1 if any
cat file.bn | burnfmt        # format standard input
```

## `burn-lsp`: the language server

`burn-lsp` is the language server over stdio, the same as `burn lsp`. Point any LSP client at it; see
[editor support](./editors.mdx).

## `bvm`: the Burn virtual machine

`bvm` runs, assembles, disassembles and verifies bvm modules. Burn programs run on it, and other languages can
target it too. See [the Burn Virtual Machine](../bvm/overview.mdx).

```sh
bvm app.bvmc                 # run bytecode (or a .bvm assembly file)
bvm asm app.bvm -o app.bvmc  # assemble
bvm dis app.bvmc             # disassemble
bvm check app.bvm            # verify without running
bvm link a.bvm b.bvmc -o c.bvmc   # link modules
bvm pack app.bvmc lib.bvmc -o app.bar   # bundle an archive; ./app.bar runs it
bvm list app.bar             # show an archive's contents
bvm runtime                  # list the runtime functions
```

## `burn`: everything in one

`burn` includes all of the above as subcommands: `burn run`, `burn build`, `burn check`, `burn test`, `burn fmt`,
`burn fix`, `burn doc`, `burn repl`, `burn eval`, `burn lsp` and `burn dump`. See the [command line reference](./cli.mdx).

## Which one should I use?

| Task | Command |
| --- | --- |
| try something quickly | `burni` |
| run a script or develop a program | `burni app.bn` |
| ship a program | `burnc app.bn` |
| ship one archive that runs where bvm runs | `burnc app.bn --target bar` |
| ship portable bytecode | `burnc app.bn --target bvm`, run with `bvm` |
| write a language or a code generator | emit bvm assembly or use the `bvm` crate |
| check a project in CI | `burnc --check` and `burnfmt --check` |
| format on save in an editor | the language server (`burn-lsp`) or `burnfmt` |
