# How the compiler works

```text
source ──▶ lexer ──▶ parser ──▶ type checker ──▶ typed IR ──▶ ownership ──▶ bvm module ──▶ bvm   (burn run)
                                    │                                              └──▶ .bvmc, .bar (burn build)
                                    ▼
                          diagnostics, hover, completion
```

The compiler is written in Burn ([`compiler/`](https://github.com/burnlang/burn/tree/master/compiler)) and runs on
bvm, like every Burn program. `burn` itself is bvm running the command line written in Burn, which contains the
compiler, so `burn run app.bn` checks, compiles and runs the program without leaving bvm.

## Front end

The lexer and a recursive descent parser build an AST. Newlines end statements, which is how `String name = x`
and `var x = a` followed by `-1` on the next line stay unambiguous. Every node carries a byte span, so every error
points at the right line and column.

The type checker resolves names across modules, checks visibility, infers types, applies smart casts with a
flow-sensitive analysis and lowers everything into a small typed IR. At that point every operation is explicit:
integer and float arithmetic are different instructions, conversions are visible, and every runtime helper call
knows the static type of its arguments.

## Runtime

All values are 64 bit words. Ints, floats, bools and enums are stored directly, everything else is a pointer to a
heap object with a 16 byte header (kind, flags, type id, size). The runtime core is part of bvm and written in
Rust (`bvm/runtime`): memory and reference counting with a cycle collector, strings, arrays, maps, boxing for
`any`, formatting, HTTP, files and async tasks. The functions built on top of it, such as `split`, `trim` or
`parseJSON`, are written in Burn (`lib/runtime`), compiled to a bvm module that bvm links into every program.

## Ownership

After type checking, an ownership pass makes memory management explicit in the IR. Every local variable, field,
array slot and map entry owns the object in it; parameters are borrowed from the caller. The pass inserts
`retain` where a borrowed value becomes owned (stored in a variable or field, returned), `release` where an owner
lets go (a variable is overwritten, a temporary has been used, the function returns), and moves instead of
copies when a local is returned. Temporaries are released at the end of the statement that created them, and
arguments read from fields or globals are kept alive for the duration of the call. Cycles are found by trial deletion over the objects whose type can form a cycle, which is
computed once from the type graph.

## bvm

`burn run` compiles the IR to a [bvm](../bvm/overview.mdx) module and runs it right away. bvm is a
general-purpose stack VM with its own assembly language, bytecode format and verifier. Burn structs become
`struct` types, interface methods become dispatch tables, `async` calls become `spawn`, and every operation that
can fail carries its source location. When the module is loaded, the verifier computes each function's frame
size and common sequences are fused into superinstructions for loops, comparisons and field access. Checking and
compiling a typical program takes a few milliseconds, so running a file feels like using an interpreter.
`burnc` writes the same module to a `.bvmc` file, and `--target bar` into an archive.

`--target js` turns the IR into one JavaScript file instead (`compiler/src/js/js.bn`), with a runtime written in
JavaScript in front of it (`lib/js/prelude.js`): every function becomes a JavaScript function, records become arrays
tagged with their type, and checked operations call small helpers that report the same runtime errors as bvm.

## Without the standard library

Programs built with `--no-std` or `std = false` link only the built-in core of the runtime, and the checker rejects
the features it leaves out ([details](./no-std.mdx)).

## Bootstrapping

The compiler builds itself. A released Burn (stage0, named in `compiler/STAGE0`) compiles `compiler/src` once; that
compiler builds itself again, and both results must be the same module (`scripts/bootstrap.sh`). Releases up to
`26.1.0-experimental-2` were compiled by a compiler written in Rust, which also had native x86-64 and JavaScript
backends; it was retired once the compiler written in Burn did everything it did.
