# Editor support

## Language server

`burn lsp` speaks the Language Server Protocol over stdio and uses the real compiler, so the editor shows exactly
the errors the compiler reports. It supports:

- diagnostics while you type, including errors in imported files
- hover with inferred types, signatures and built-in documentation
- completion for locals, globals, functions, types, keywords (including `struct`, `abstract`, `new` and `destroy`),
  built-ins and members after `.`
- go to definition, including into imported modules
- document outline
- formatting (the same as `burn fmt`)

Any editor with LSP support can use it. Import paths complete too: standard modules, the project's packages and
local files inside `import "..."`.

## Neovim

With Neovim 0.11 or newer (and LazyVim, as `~/.config/nvim/lua/plugins/burn.lua`):

```lua
return {
  "neovim/nvim-lspconfig",
  init = function()
    vim.filetype.add({ extension = { bn = "burn" } })
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "burn",
      callback = function()
        vim.bo.commentstring = "// %s"
      end,
    })
    vim.lsp.config("burn", {
      cmd = { "burn", "lsp" },
      filetypes = { "burn" },
      root_markers = { "burn.toml", ".git" },
    })
    vim.lsp.enable("burn")
  end,
}
```

Without LazyVim, put the body of `init` into `init.lua`. On older versions of Neovim start the server from a
`FileType` autocommand with `vim.lsp.start({ name = "burn", cmd = { "burn", "lsp" }, root_dir =
vim.fs.root(0, { "burn.toml", ".git" }) })`. `burn` must be on the `PATH` Neovim sees; burnup puts it in
`~/.burn/bin`.

## VS Code

The extension lives in `editors/vscode`. It adds syntax highlighting, snippets, the language server client and
commands to run, natively run and build the current file. Snippets include `defstruct`, `defabstract` and
`defstatic` for the three kinds of struct, `new` and `destroy`.

```sh
cd editors/vscode
npm install
npx vsce package
code --install-extension burn-language-server-26.1.0.vsix
```

Set `burn.path` if `burn` is not on your `PATH`.
