# Editor support

## Language server

`burn lsp` speaks the Language Server Protocol over stdio and uses the real compiler, so the editor shows exactly
the errors the compiler reports. It supports:

- diagnostics while you type, including errors in imported files
- all features keep working while the code is incomplete: `p.` with nothing after it, a call without its `)`, or a
  block whose `}` is not typed yet
- hover with inferred types, signatures and built-in documentation
- completion for locals, globals, functions, types, keywords (including `struct`, `abstract`, `new` and `destroy`),
  built-ins and members after `.`, with the signature and docs of each built-in. Members include inherited fields and
  methods and every function that can be called as a method (`text.upper()`). Functions complete with their
  parentheses and show their parameters
- completion of names from standard modules that are not imported yet; picking one adds the `import`
- clickable imports: `import "std/date"` and `import "shapes.bn"` are links, and hovering one lists what the module
  exports
- signature help while you type the arguments of a call, for functions, constructors, methods and built-ins
- inlay hints with the inferred type of `var`, `const` and `for` variables that have no annotation
- go to definition, including into imported modules, the standard library, built-in functions and the exported
  functions of bytecode libraries
- go to type definition, and go to implementation (the structs that implement an interface or extend a struct, and
  the methods that implement an interface method)
- find references, highlight references and rename across all files of the project; renaming an interface method
  also renames the methods that implement it
- workspace symbols, an outline with the fields and methods of each struct, and folding of blocks, comments and imports
- formatting (the same as `burn fmt`), quick fixes from the compiler, **Import ...** fixes for names from standard
  modules and project files, and **Fix all** (also as `source.fixAll.burn` for `editor.codeActionsOnSave`)

Any editor with LSP support can use it. Import paths complete too: standard modules, the project's packages and
local files inside `import "..."`.

### Library sources

The standard library and the built-ins are compiled into `burn`, so there is no file to jump to. When you go to the
definition of `println` or of a function from `std/date`, the server writes the source once to
`~/.burn/cache/sources/<version>/` (under `$BURN_HOME` when it is set) and opens it there:

- `builtins.bn` declares every built-in function with its documentation
- `std/<module>.bn` is the real source of each standard module
- `libs/<library>.bn` lists the functions a `.bvmc` bytecode library exports, with their types

The files are read-only and cannot be renamed into. `burn sources` writes all of them at once and prints the folder,
which is handy for browsing or searching the standard library.

## Neovim

With Neovim 0.11 or newer (and LazyVim, as `~/.config/nvim/lua/plugins/burn.lua`):

```lua
return {
  "neovim/nvim-lspconfig",
  init = function()
    vim.filetype.add({ extension = { bn = "burn" } })
    vim.api.nvim_create_autocmd("FileType", {
      pattern = "burn",
      callback = function()
        vim.bo.commentstring = "// %s"
      end,
    })
    vim.lsp.config("burn", {
      cmd = { "burn", "lsp" },
      filetypes = { "burn" },
      root_markers = { "burn.toml", ".git" },
    })
    vim.lsp.enable("burn")
  end,
}
```

Without LazyVim, put the body of `init` into `init.lua`. On older versions of Neovim start the server from a
`FileType` autocommand with `vim.lsp.start({ name = "burn", cmd = { "burn", "lsp" }, root_dir =
vim.fs.root(0, { "burn.toml", ".git" }) })`. `burn` must be on the `PATH` Neovim sees; burnup puts it in
`~/.burn/bin`.

## VS Code

The extension lives in `editors/vscode`. It adds syntax highlighting, snippets, the language server client and:

- **Run | Run natively | Build** links above `fun main` (turn them off with `burn.codeLens.run`) and a run button
  in the editor title
- **Burn: Open Standard Library Module...** and **Burn: Show Built-in Functions** to read the library sources
- library sources open read-only, so they are not edited by accident
- the Burn version in the status bar; clicking it restarts the language server
- a warning when the installed `burn` is older than the extension and misses language server features

To fix everything that can be fixed whenever you save, add this to your settings:

```json
"[burn]": {
  "editor.codeActionsOnSave": { "source.fixAll.burn": "explicit" }
}
```

Snippets include `defstruct`, `defabstract` and `defstatic` for the three kinds of struct, `new` and `destroy`.

```sh
cd editors/vscode
npm install
npx vsce package
code --install-extension burn-language-server-26.2.0.vsix
```

Set `burn.path` if `burn` is not on your `PATH`.

## JetBrains IDEs

The plugin in `editors/jetbrains` works in IntelliJ IDEA, CLion, RustRover, PyCharm, GoLand, WebStorm and the other
JetBrains IDEs from 2024.2 on. It uses [LSP4IJ](https://github.com/redhat-developer/lsp4ij) for the language server,
so the IDE installs LSP4IJ along with it, and the TextMate grammar of the VS Code extension for highlighting. You get
everything the language server offers: completion, hover, parameter info, inlay hints, go to declaration (also into
the library sources), find usages, rename, formatting and quick fixes. **Tools | Burn** and the editor context menu
run, natively run and build the current file, open a standard module or show the built-ins.

```sh
cd editors/jetbrains
gradle buildPlugin
```

This needs JDK 21 and Gradle 9 or newer. Install `build/distributions/burn-intellij-26.2.0.zip` with **Settings |
Plugins | Install Plugin from Disk...**. CI builds the same zip as an artifact of the Editors workflow.

The plugin starts `burn lsp` from your `PATH`, `$BURN_HOME/bin` or `~/.burn/bin`. **View | Tool Windows | Language
Servers** shows the server and its log.

## Zed

The Zed extension in `editors/zed` uses the tree-sitter grammar in `editors/tree-sitter-burn` for highlighting,
outline, indentation and bracket matching, and starts `burn lsp` for everything else. A run button appears next to
`fun main`, and the tasks `burn run`, `burn run --native` and `burn build` work on the current file.

To install it, run **zed: install dev extension** and choose `editors/zed`. Zed needs Rust installed through rustup
to build it. To use another `burn`, set the path in Zed's settings:

```json
{
  "lsp": {
    "burn": {
      "binary": { "path": "/path/to/burn", "arguments": ["lsp"] }
    }
  }
}
```

## Tree-sitter

`editors/tree-sitter-burn` is a tree-sitter grammar for Burn with highlight queries. Zed uses it, and Neovim (through
nvim-treesitter), Helix and other tree-sitter editors can too. After changing `grammar.js`, regenerate the parser and
run the tests:

```sh
cd editors/tree-sitter-burn
tree-sitter generate --abi 14
tree-sitter test
```
